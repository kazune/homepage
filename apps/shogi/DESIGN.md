# 将棋アプリの設計方針

この文書は `.idea/shogi.md` を起点にした議論の合意をまとめる。
型の例は設計を説明するもので、未確定の項目は末尾に分ける。

## 基本方針

- 通常駒と多段移動駒を、同じシーケンス構造で扱う。
- 移動は `vector + range + pass + land` で表す。
- 候補表示は現在の段の着地点だけを対象とし、後続段の成立は先読みしない。
- 駒の定義は不変とし、位置の変化を `Transfer` として記録する。
- 特殊な規則をすべて汎用モデルへ押し込めず、必要に応じて専用処理を書く。
- ブラウザ内で完結する、小さく読みやすい TypeScript の実装にする。

## 移動規則の構造

```text
PieceType
 └─ SequenceRule[]
     └─ SequenceStage[]
         └─ MovementRule[]
             ├─ vector
             ├─ range
             ├─ pass
             └─ land
```

各配列の意味は次のとおり。

- `SequenceRule[]`：選択可能な移動シーケンス。
- `SequenceStage[]`：そのシーケンスで順番に実行する段。
- `MovementRule[]`：その段で選択可能な移動規則。

通常駒は段数が1のシーケンスを持つ。例えば飛車は、1段の中に4方向の移動規則を持つ。
多段移動駒は段数が2以上のシーケンスを持つ。

```ts
type SequenceRule = Readonly<{
  stages: readonly SequenceStage[];
}>;

type SequenceStage = Readonly<{
  movements: readonly MovementRule[];
}>;
```

### 途中終了

途中で手を終了できる場合は、その長さのシーケンスを別に定義する。
`canStop` などの属性は追加しない。定義の数が増えすぎる場合に再検討する。

例えば `[A]` と `[A, B]` を定義すると、Aまで実行して終了する手と、Bへ続ける手を表せる。
共通する段を進める間は、選択に適合するシーケンスを候補として保持する。
あるシーケンスが完了し、別のシーケンスが続行可能なら、終了と続行を選べる。

### 各段の評価

各段の `from` は直前の着地点とする。最初の段だけは、その手の開始位置を使う。
次段は、それまでの移動と捕獲を反映した仮盤面で評価する。
出発地点へ戻る移動も、この仕組みで扱う。

現在の段を選択した後、次段の候補が存在しなくても、事前には除外しない。
完了したシーケンスがなく、続行も不能になった段階で「合法に移動を終了できません」と表示する。
ユーザーは「待った」でその手の開始時点へ戻って選び直せる。

## 1段の移動

### ベクトルと距離

`vector` は1回分の変位、`range` はその反復回数のうち着地できる範囲を表す。

移動定義の基本関数は `ray(vector, max)` とし、反復回数1から `max` までを候補とする。`null` は上限なし。
`step(vector)` は `ray(vector, 1)`、`slide(vector)` は `ray(vector, null)` の略記とする。
複数方向の補助関数は `steps`・`slides` と命名する。猛牛などの距離制限付きの走り移動には `ray(vector, 2)` を使う。
距離は実際のマス数ではなく、ベクトルの適用回数。

- 歩：`[0, -1]` を1回。
- 桂馬：`[-1, -2]` または `[1, -2]` を1回。
- 飛車：上下左右の単位ベクトルを、盤外に出るまで反復。

ベクトルはプレイヤー基準で定義する。
評価時にプレイヤーに応じた回転変換を適用し、盤面座標の変位へ変換する。

上限なしの距離は `max: null` とする。探索は盤外に出たら終了する。
ゼロベクトルは繰り返し評価せず、1回だけ評価する。

ゼロベクトルは `distance: 1` として `land` を1回だけ評価し、`pass` は呼ばない。
`target` は元のマスにいる移動駒自身とする。距離1が `range` の着地範囲に含まれる場合に候補となる。
その場に留まる「じっと」を許可するか、どのような効果を起こすかは `land` に任せる。
「じっと」の許可は専用の `land` に限定せず、`landNormal` で移動駒自身への着地を許可してもよい。
その場合、自身の捕獲効果は発生させず、他の味方駒への着地とは区別する。
「じっと」を候補に含める駒には、ゼロベクトルの移動規則を定義する。

### 通過と着地

ある着地点の評価では、その着地マスを `pass` の対象に含めない。

例えば距離3に着地するなら、距離1・2に `pass`、距離3に `land` を適用する。
同じマスでも、そこに着地する候補では `land`、さらに先へ進む候補では `pass` の対象となる。
距離1だけの移動には通過マスがないため、桂馬の移動で途中のマスは検査しない。

探索をまとめて行う場合は、各マスで着地可能性を評価し、その先へ進むための通過判定を行う。
通過できないマスでも着地できる場合があるため、通過失敗によってそのマスの着地候補を失わせない。
`range.min` 未満のマスも、先へ進むには通過判定が必要。

### 判定と効果

`pass` と `land` は許可・不許可と、捕獲などの効果を返す。
候補を表示するだけなら、捕獲対象の一覧を候補に保存する必要はない。
選択された移動の実行時に通過と着地を再評価し、効果を収集して適用する。

例えば格下を薙ぎ倒す駒がA、Bを通過して空マスCに着地する場合、実行時にはAとBの捕獲を適用する。
候補生成中に盤面を変更しない。

現在の段で可能な選択は、候補として残っているシーケンスと各移動規則の着地点の和集合として表示する。
同じ着地点は重複表示しない。選択後も、その選択に適合するシーケンスをすべて保持する。
同じ段で同じ着地点へ移動できる規則の効果が異なる場合はエラーとし、移動方法を選ばせるUIは設けない。
効果の比較には通過マスと着地マスの効果を含める。
この整合性確認のために効果を調べる場合も、候補の戻り値に捕獲対象一覧を保持する必要はない。

1段の中では、候補生成時も実行時も、`pass` と `land` はその段を開始した時点の盤面を参照する。
選択された着地点までの効果を収集し、移動とともにまとめて適用する。
次段は、その移動と効果を反映した盤面で評価する。
途中の捕獲によって同じ段の後続判定が変わる特殊規則は、専用処理で扱う。

格による捕獲は、基本的には敵味方を区別しない。
区別が必要な規則では、`pass` や `land` の条件に所有者の判定を書く。

### 特殊規則

獅子のような多段移動も、段の進行自体は共通のシーケンス構造で扱う。
中将棋の獅子や自在天王など、各段の条件や効果に特殊な規則が必要な場合は専用処理を用意する。
すべてを表現するために基本モデルを複雑化しない。

## 駒と位置

### 駒種の属性と参照

格と王族属性は個体ごとに持たず、駒種で決まる。

```ts
type PieceType = Readonly<{
  id: PieceTypeId;
  name: string;
  rank: number;
  royal: boolean;
  sequences: readonly SequenceRule[];
}>;
```

成りによって別の駒種になる場合は、その駒種の格と王族属性を使う。
格の概念がないゲームでは `rank` を0などで統一する。

`pass` と `land` の判定コンテキストには、駒から駒種を参照する `pieceTypeOf` を渡す。

```ts
type MovementContext = Readonly<{
  board: Board;
  mover: Piece;
  from: Position;
  position: Position;
  distance: number;
  pieceTypeOf: (piece: Piece) => PieceType;
}>;
```

格の比較は `pieceTypeOf(target).rank < pieceTypeOf(mover).rank` のように行う。
判定に必要な参照を渡し、ゲーム全体への参照は持たせない。

### 駒の個体と位置

駒の定義と現在位置を分離する。

```ts
type Piece = Readonly<{
  id: PieceId;
  type: PieceTypeId;
  owner: PlayerId;
}>;

type Location =
  | BoardLocation
  | HandLocation
  | VoidLocation;

type BoardLocation = Readonly<{
  kind: "board";
  position: Position;
}>;

type HandLocation = Readonly<{
  kind: "hand";
}>;

type VoidLocation = Readonly<{
  kind: "void";
}>;
```

- `BoardLocation`：盤上の位置。
- `HandLocation`：持ち駒の位置。
- `VoidLocation`：盤上・持ち駒から除外された状態。

誰の持ち駒かは `Piece.owner` で判断し、`HandLocation` に所有者を重複して持たせない。
持ち駒は並び順やスロットを持たず、表示時に所有者・駒種でまとめる。
`VoidLocation` は除外理由を持たない。

`Piece` のID・駒種・所有者は生成後に変更しない。
現在位置は別に保持し、各駒は常にいずれかの `Location` に属する。

## 履歴とundo

駒の状態変化を位置間の移送として記録する。

```ts
type Transfer = Readonly<{
  pieceId: PieceId;
  from: Location;
  to: Location;
}>;

type Transaction = Readonly<{
  playerBefore: PlayerId;
  playerAfter: PlayerId;
  transfers: readonly Transfer[];
}>;
```

実行時は `transfers` の順に適用する。
undoでは逆順に処理し、各 `from` と `to` を交換する。
捕獲と移動など、まとめて戻す必要のある変更は同じトランザクションに入れる。

1トランザクションを1手番とする。多段移動でも段ごとに分けない。
ターン中は、各段の移動と効果を適用するたびに `transfers` を追加してトランザクションを育てる。
`Readonly` の値を直接変更せず、追加した新しい値へ置き換える。
すでに適用した移送は再適用しない。

ターン中は `playerAfter === playerBefore` とする。
手が完了したら `playerAfter` に次のプレイヤーを設定し、手番を更新して履歴に確定する。

### 成りと持ち駒化

成り・持ち駒・駒打ちのルールはゲームごとに定義する。
成りの可否と任意・強制の区別、捕獲後に持ち駒にするか、持ち駒化するときの駒種、打てる場所などはゲーム側で判定する。
共通処理はその判定結果に従って駒を生成し、`Transfer` を作成して適用する。
特定のゲームの条件を共通の移動処理へ組み込まない。

元の駒を除外し、別の定義を持つ新しい駒を生成する。
`Piece.type` や `Piece.owner` の変更履歴は持たない。

成りの例：

```text
元の歩：盤上 → Void
新しいと金：Void → 同じ盤上位置
```

捕獲して持ち駒にする例：

```text
捕獲された駒：盤上 → Void
捕獲側が所有する不成の新しい駒：Void → 持ち駒
```

新しい駒には新しいIDを割り当て、初期位置を `Void` として登録する。
生成した駒の定義はundo後も保持する。undoは新しい駒を `Void` へ戻し、元の駒を復帰させる。
redoを行う場合も、同じIDと定義を再利用できる。

### 進行状態の復元

「待った」は、その手全体を取り消す。

- ターン中：育てているトランザクションを逆適用し、その手の開始時点へ戻す。
- 手の完了後：最後に確定したトランザクションを逆適用する。

どちらも手番を `playerBefore` に戻し、段やシーケンスの選択状態を破棄する。
段ごとの履歴や進行状態のスナップショットは保持しない。

## 王族と決着

王の安全性は検査しない。王を捕獲してよく、詰みチェックも実装しない。

王や太子などの駒種には `royal: true` を設定する。
決着はゲームごとの条件で判断する。例えば「自分の王族が0個になったら負け」とする。
王族の存在を数える際は、除外された駒の定義が残っていても、生存扱いにしない。

決着は、成りなども含めて手が完了した時点で判定する。
多段移動の途中で王族が0個になっても、その時点では決着とせず、残りの段を実行できる。
双方が敗北条件を満たした場合は引き分けとする。

## 特殊規則への違反と反則負け

先獅子・後獅子などの特殊規則を追加する場合も、移動可能なマスの表示は変更しない。
特殊規則による候補の除外や、後続段の先読みは行わない。

成りを含む一手を完了した後、ゲーム固有の規則でその手全体を検査する。
違反していた場合は手を確定し、指したプレイヤーの反則負けとする。
手の終了を拒否したり、自動で盤面を戻したりはしない。
反則の理由を表示し、対局終了後の「待った」は引き続き利用できるようにする。

判定には、必要に応じて手の開始盤面、終了盤面、現在のトランザクション、直前の確定済みトランザクションを使う。
多段移動も一手全体として検査し、途中で隣接したことだけを理由に制限を解除しない。
判定結果は対応する手とともに扱い、「待った」でその手の移送・手番と反則負けを取り消す。
この方針は判定のタイミングとUIの扱いを定めるもので、先獅子などの具体的な条件や例外は別途定義する。

### 中将棋の先獅子・後獅子

中将棋では `GameDefinition.validateTurn` に一手の検査を定義する。
直前の手で獅子以外の駒が獅子を捕獲した場合、その直後の手で足のある相手の獅子を捕獲すると反則負けにする。
日本中将棋連盟の補足規則に合わせ、手の開始時点で隣接する獅子同士の捕獲と、歩兵・仲人以外を先に捕獲する獅子の付け喰いは例外とする。
麒麟から成った獅子も獅子として扱い、麒麟が獅子を取りながら成った場合にも先獅子を適用する。

足は手の開始盤面を基準とし、捕獲側の出発位置を空けたときの走り駒の利き（かげ足）も数える。
味方駒の利きは共通の移動評価を使い、特殊規則の検査へ再帰しない。
後獅子の専用フラグは持たず、直前の確定済みトランザクションから条件を導出する。

一手の開始盤面は、検査時に終了盤面へトランザクションを逆適用した位置情報から復元する。
検査結果はトランザクションに対応付け、履歴からその手を取り除けば反則負けも解消する。
反則負けは王族の捕獲による決着より優先する。
先獅子と関係なく、足のある獅子を獅子で取ることも制限する。
手の開始位置から距離1での捕獲と、歩兵・仲人以外を先に捕獲する付け喰いは例外とする。
途中の段で隣接しても、手の開始位置から距離2なら距離1の例外は適用しない。
こちらも候補を除外せず、一手の完了後に違反理由を表示して反則負けとする。

### 通常将棋の持ち駒と反則

`GameDefinition.captureToHand` は捕獲された駒に対応する持ち駒の駒種を返す。
通常将棋では不成の駒種に戻し、捕獲側を所有者とする新しいIDの駒を生成する。王は持ち駒にしない。
中将棋はこの関数を定義せず、捕獲された駒を除外する。

`HandLocation` に所有者は持たせず、駒自身の `owner` で区別する。
`GameDefinition.canDrop` を定義したゲームで持ち駒を選ぶと、空きマスを候補として表示する。
駒打ちは同じIDの駒を持ち駒から盤上へ移送する一手で、成りの選択は発生しない。
捕獲による生成と駒打ちは既存の移送履歴に含め、待ったで復元する。

通常将棋の `validateTurn` は、指した側の終了盤面について二歩と行き所のない駒を検査する。
同じ筋の不成の歩が2枚あれば二歩。歩・香の最奥段、桂の最奥2段への不成での配置は反則とする。
方向は所有者に応じて反転し、成りの選択後に検査する。成った歩は二歩に数えない。
駒打ちの候補にも反則となるマスを含め、違反した手の終了後に反則負けを表示する。
打ち歩詰め、王の安全性、詰み、千日手は検査しない。

### どうぶつしょうぎの定義

3×4盤・各4枚。駒の移動・成り先・持ち駒化・駒打ちはゲーム定義で表し、共通エンジンの型やAPIを拡張しない。
ひよこの最奥段への移動では既存の成り確認を使い、不成なら `validateTurn` で反則負けとする。駒打ちは成りの検査対象にしない。

トライも `validateTurn` で表す。指した側の手の終了盤面で、相手のライオンがその相手にとっての最奥段に残っていれば、指した側の負けとする。
画面では勝者と判定理由を表示し、理由のある決着を一律に「反則負け」とは表示しない。
ライオンの進入直後には決着せず、相手に一手を与える。利きによる安全性判定は導入しない。
二歩・打ち歩詰め・最奥段へのひよこ打ちは禁止せず、千日手は判定しない。

### 禽将棋の定義

禽将棋は7×7盤・各16枚。専用の9種類の駒を `toriPieceTypes` に定義する。
左右の鶉は別の駒種として保持し、所有者に応じた方向変換を適用する。
雉・鴈の跳躍は `step` のベクトル、鵰の後ろ斜め1〜2マスは `ray` で表す。
持ち駒化・駒打ち・待ったは共通処理を使い、鴈を燕、鵰を鷹に戻す。鵬は王族属性を持ち、持ち駒にしない。

燕・鷹は敵陣2段に関わる移動で成りが必須。共通の成りconfirmを使い、拒否された場合は `validateTurn` で反則負けにする。
移動した元の駒が終了盤面に残っているかで不成を判定する。駒打ちは成りの対象としない。
同じ筋の不成の燕が3枚になる手と、最奥段への燕打ちも終了盤面で検査する。
候補表示では除外せず、「待った」で反則負けごと戻せる。共通エンジンの型やAPIは拡張しない。
王の安全性・詰み・打ち燕詰め・千日手は他の将棋と同様に判定しない。

### 大将棋の定義

大将棋は15×15盤・各65枚。中将棋と共通の駒は `chuPieceTypes` の移動・成り定義を再利用する。
追加8種類は金将への成りを定義し、成った駒の駒種を別IDにして二度目の成りを防ぐ。
猛牛と飛龍の2マス移動は `range.max: 2` と空きマスの通過条件で表し、跳躍にはしない。

成りの領域は敵陣5段。進入、または敵陣に関わる捕獲で成りを選べる。
最奥段での成りの追加機会は設けず、不成のまま動けなくなる配置も許可する。
持ち駒の変換・駒打ち・獅子の捕獲制限の関数は定義しない。
王将と太子の全捕獲による決着と、一手全体の待ったは共通処理を使う。

### 大局将棋の定義

大局将棋は36×36盤・各402枚。他の将棋と同名の駒も動きが異なるため、専用の移動データを共通モデルへ変換する。
折れ曲がる移動と跳躍後の走り移動はシーケンスで表し、捕獲して終了する短いシーケンスと空きマスに着地して続く長いシーケンスを分ける。
奔鷲は跳躍を1段で、通過する各マスでの捕獲を3〜4段で定義する。同方向の捕獲列の途中終了は許可しない。

格による通過捕獲は `pass`・`land` が格下の駒の捕獲効果を返す。敵味方の区別はしない。
最大3枚の駒を飛び越える動きは、`pass` で起点から現在マスまでの駒を数える。探索間で可変のカウンターは共有しない。
成りは敵陣11段に関わる移動で任意に選ぶ。強制成りは採用せず、共通の成りAPIは拡張しない。
王将と太子の全捕獲、移送履歴、手番、待ったも共通処理を利用する。
調査と採用方式の詳細は [TAIKYOKU.md](./TAIKYOKU.md) を参照。
