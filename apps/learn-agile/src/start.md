# 2〜5人でアジャイルを始めよう

このガイドは、アジャイル開発を学んだ高校生2〜5人が、実際に最初の1週間を始めるためのスターターキットです。文化祭サイトの例を見ながら、自分たちの活動に使うシートを作ります。

> **1週間の目標**
>
> 小さくても実際に使えるものを一つ完成させ、利用する人に見せ、得た学びから次にすることを決める。

すべての機能を完成させる必要はありません。最初の1週間で、次のサイクルを一度回すことを目指します。

# 0. 始める前に用意するもの

最初に必要なのは、高価なツールや詳しい計画ではありません。次の四つを用意します。

- 2〜5人のチーム
- 実際に困っている人、または使って確認してくれる人
- 一週間に何度か集まれる時間
- 仕事と決定を全員で見られる場所

仕事を見えるようにする場所は、模造紙と付箋でも、共有できるオンラインのボードでも構いません。全員が迷わず確認できる方法を一つ選びます。

## 実際に確認してくれる人を先に決める

週末に見せる相手を、始める前に決めます。「完成したら誰かを探す」では、チームの予想だけで終わりがちです。

文化祭サイトなら、来場者に近い別クラスの生徒、出展する生徒、実行委員などが考えられます。作る人とは違う立場の人に協力してもらいます。

# 1. チームと役割を決める

2〜5人の小さなチームでは、役職を細かく分けすぎる必要はありません。最初の一週間は、次の責任が誰にあるかを明確にします。

| 責任 | すること | 決め方の例 |
|---|---|---|
| 価値と優先順位 | 誰の何を良くするかを明確にし、迷ったときに優先順位を決める | 目的を最もよく知る1人 |
| 成果を作る | 設計、文章、実装、確認など、完成に必要な仕事を協力して行う | チーム全員 |
| 進行と改善 | 話し合いの目的と時間を守り、困りごとや振り返りを見えるようにする | 1人または日替わり |

一人が複数の責任を持っても構いません。ただし、価値と優先順位の最終判断を誰がするかは、始める前に決めます。

## チームの約束

最初は、次の四つで十分です。

- 分からないことを隠さない
- 困ったら決めた時間内に共有する
- 人ではなく、成果と進め方について話す
- 大切な決定を全員が見られる場所へ残す

# 2. プロジェクトを1枚で共有する

最初に長い企画書を作らず、次の五つを一枚にまとめます。答えが分からない項目は、空欄にせず「未確認」と書き、誰に確認するか決めます。

## 記入例：文化祭サイト

| 項目 | 記入例 |
|---|---|
| 誰が困っているか | 初めて文化祭へ来る人 |
| どんな場面で困るか | 出し物一覧から見たい企画を探すとき |
| 今の問題 | 一覧が長く、見つける前に諦める人がいる |
| 良くしたい状態 | 興味のある出し物を短時間で見つけられる |
| 確認してくれる人 | 別クラスの生徒3人 |
| 今回は作らないもの | 場所検索、人気順、コメント投稿 |

## 自分たちのプロジェクトシート

全員がこの内容を自分の言葉で説明できるか確認します。意見が違ったら、作り始める前に話し合います。

# 3. 最初のバックログを作る

良くしたい状態へ近づく仕事を、まず3〜5件だけ出します。最初から将来の仕事をすべて書く必要はありません。

## 一つの項目に書くこと

- **誰のためか:** 主に利用する人
- **良くなること:** その人ができるようになること
- **完了条件:** 何を確かめたら完成か
- **不明点:** 作る前や作りながら確認すること

## 記入例

| 優先 | 仕事 | 完了条件 | 不明点 |
|:---:|---|---|---|
| 1 | 名前の一部で出し物を検索できる | 入力に合う出し物だけが表示される | 表記の違いを扱うか |
| 2 | 結果がないとき案内する | 次に何をすればよいか分かる | 案内の文章 |
| 3 | 場所で絞り込める | 選んだ場所の出し物だけが表示される | 場所データがそろっているか |

一週間で完成させるのは、優先順位1のうち、さらに小さくした範囲です。簡単だからではなく、目的へ近づき、早く確かめる価値があるものを選びます。

# 4. 今週のゴールと範囲を決める

30分を目安に、今週の目的と完成させるものを決めます。

## 記入例

> **今週のゴール:** 来場者が、名前を覚えている出し物を一覧から短時間で見つけられる。
>
> **完成させるもの:** 出し物の名前の一部を入力すると、合うものだけが表示される。結果がない場合は案内する。
>
> **今回はしないこと:** 場所やジャンルでの検索、表記の自動変換。
>
> **確かめたいこと:** 初めて使う人が検索欄に気づき、目的の出し物を見つけられるか。

## 自分たちの今週シート

- **今週のゴール:**
- **完成させるもの:**
- **今回はしないこと:**
- **確かめたいこと:**
- **週末に見せる相手と日時:**

完成させるものが多すぎる場合は、「このうち一つだけでも利用者へ見せられるか」を考えて小さくします。

# 5. 「完了」を全員でそろえる

作る人によって完成の意味が変わらないよう、共通のチェックリストを決めます。最初は次をそのまま使えます。

## 完了チェックリスト

- [ ] 今週のゴールに関係する成果である
- [ ] 決めた完了条件を満たしている
- [ ] 実際に操作でき、途中で止まらない
- [ ] 作った本人以外が確認した
- [ ] 以前できていた大切な動きを壊していない
- [ ] 利用者へ見せられる状態になっている
- [ ] 残っている問題や未確認の点を共有した

すべてを完璧にするという意味ではありません。今回決めた範囲で、安心して使い、フィードバックを得られる状態を表します。

# 6. 一週間を回す

学校生活に合わせ、無理なく集まれる時間で決めます。次は一例です。

| 日 | 活動 | 目安 | 結果として残すもの |
|---|---|---:|---|
| 1日目 | 目的、ゴール、範囲を決める | 45分 | プロジェクトシート、今週シート |
| 2〜4日目 | 作る、毎日確認する | 毎日10分＋作業時間 | 完成へ近づく成果、困りごと |
| 4日目 | 途中の成果をチームで確認する | 20分 | 修正する点、残りの範囲 |
| 5日目 | 利用者レビュー | 30分 | 観察した事実、フィードバック |
| 5日目 | 振り返り | 20分 | 次回試す改善を一つ |

毎日会えない場合は、共有場所に同じ内容を残します。ただし、困りごとは次の予定まで待たずに共有します。

## 毎日の10分確認

一人ずつ長い報告をするのではなく、今週のゴールを見ながら全員で確認します。

- [ ] ゴールへ近づくために、何が完了したか
- [ ] 次に行う小さなことは何か
- [ ] 分からないこと、止まっていることは何か
- [ ] 他の人の助けや確認が必要か
- [ ] 今週の範囲を変える必要があるか

詳しい相談は、必要な人だけで10分確認の後に行います。

# 7. 利用者レビューをする

完成した機能の説明会ではなく、利用する人に実際の目的を達成してもらいます。検索機能なら、「オバケ屋敷を探してください」のように目的を伝え、操作方法は教えずに観察します。

## 30分の進め方

1. **目的を共有する（3分）:** 何を良くしたくて作ったか伝える
2. **使ってもらう（12分）:** 説明しすぎず、行動と迷いを観察する
3. **質問する（10分）:** 良かった点、困った点、期待との違いを聞く
4. **事実を整理する（5分）:** すぐ直す約束をせず、分かったことを確認する

## レビューメモ

| 観点 | 記録すること |
|---|---|
| できたこと | 目的を達成できた場面 |
| 迷ったこと | 止まった場所、予想外の操作 |
| 聞いたこと | 利用者の言葉や要望 |
| 新しく分かったこと | チームの予想との違い |
| まだ分からないこと | 次に確かめる必要がある点 |

要望をすべて次の仕事にせず、背景にある困りごとを考えます。

# 8. 20分で振り返る

利用者レビューの後、成果ではなくチームの進め方を振り返ります。誰かを評価する場にしません。

## 進め方

1. **事実を出す（5分）:** 今週起きたこと
2. **意味を考える（5分）:** 何が助けになり、何が妨げたか
3. **改善案を出す（5分）:** 次回試せる小さな変更
4. **一つ選ぶ（5分）:** 誰が、いつ行うか決める

## 振り返りシート

| 質問 | 自分たちの記録 |
|---|---|
| うまくいったことは何か |  |
| 困ったことは何か |  |
| そこから何を学んだか |  |
| 次の一週間で変えることを一つ |  |
| 誰が、いつ最初に行うか |  |
| 役立ったかをどう確かめるか |  |

「もっと話し合う」のような曖昧な案ではなく、「毎日の確認で最初に困りごとを聞く」のように、実行する場面が分かる形にします。

# 9. 次の一週間を決める

レビューで得た学びと、振り返りで選んだ改善を使い、次の一週間を始めます。

- 目的へどれくらい近づいたか
- 最初の予想と何が違ったか
- 次に最も価値がある仕事は何か
- 今回の範囲をさらに小さくできるか
- チームの進め方を何一つ変えるか

最初のバックログの順番を、そのまま守る必要はありません。新しく分かったことから、目的へ最も近づくものを選び直します。

# うまく回らないとき

## 一週間で完成しなかった

誰かを責めず、完成しなかった範囲を確認します。次は仕事をさらに小さくし、利用者へ見せられる最小の部分を先に完成させます。

## 毎日の確認が報告会になった

一人ずつの作業量ではなく、「今週のゴールへ近づいているか」「助けが必要か」を全員で確認します。

## 利用者が要望をたくさん出した

その場ですべて作る約束をしません。どんな困りごとが背景にあるかを聞き、目的と影響から優先順位を決めます。

## 振り返りで意見が出ない

「良かったこと」「困ったこと」を各自で一つ書いてから共有します。大きな改善ではなく、次の一週間で一度試せる変更を探します。

# 開始前の最終チェック

- [ ] 2〜5人のメンバーが決まっている
- [ ] 実際に確認してくれる利用者と日時が決まっている
- [ ] 誰の何を良くしたいか、一枚で共有できる
- [ ] 最初のバックログが3〜5件ある
- [ ] 今週のゴールと、作らない範囲が決まっている
- [ ] チーム共通の完了条件がある
- [ ] 毎日の確認、レビュー、振り返りの時間が決まっている
- [ ] 困ったときの共有方法と相談相手が分かる

全部そろったら、最初の小さな仕事を一つ選んで始めましょう。
